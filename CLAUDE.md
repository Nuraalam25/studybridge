# CLAUDE.md

This file covers the code. The competition, the plan, and the rules for evidence and claims are in
[../CLAUDE.md](../CLAUDE.md); the plan itself is `../StudyBridge_Final_Plan_v4.docx` (its §2c lists the changes made after v4).
This repo implements it as v0.5.0.

## Commands

Python 3.10+, **standard library only** (no requirements file, no third-party deps; keep it that way). Local git repo (no remote); `pyright studybridge` type-checks, but most of its errors are false positives from `= None` defaults and `fail()` in `gate1` not being typed `NoReturn`.

```bash
python -m unittest discover -s tests -t .                                  # all 254 tests (~7s)
python -m unittest tests.test_payments.TestStories                         # the 31 stories
python -m unittest tests.test_security.TestInjection.test_detector         # one test
python -m studybridge --today 2026-10-13 --tier TRANSACT web               # UI on http://127.0.0.1:8765 (add --state FILE to keep state across restarts)
python -m studybridge --today 2026-10-13 demo --out <scratch dir>          # trial run: 31 stories + 5 info requests (evidence/ only after the freeze)
python -m studybridge --llm --today 2026-10-13 demo                        # same with qwen2.5:7b (~5-6 min); with GROQ_API_KEY set it uses the hosted Qwen instead
python -m studybridge --audit <path.jsonl> verify-audit                    # exit 1 if the hash chain is broken or cut short
```

Global flags go **before** the subcommand. `--tier` defaults to ADVISE, which cannot pay; use TRANSACT for payments. The UI reads static files from disk on every request, but Python changes need a server restart.

## Architecture

Core rule: **AI suggests, code decides, the student confirms last.** Qwen only parses and explains, and never owns a number, a permission, an actor or an approval.

- [studybridge/agent.py](studybridge/agent.py) runs the 11-step workflow (the `PIPELINE` constant; step keys "1"–"11", with "6a" for tuition and "6b/7b/8b" for everyday). `handle()` is for student chat; `family_decide()`, `confirm()`, `ack_alert()` and the other actor methods sit outside chat. Each message opens a **case** (`self.cases`) whose steps, Gate 1 checks and `glass` (rules vs Qwen vs final parse; what Qwen was sent and wrote) feed the Glass Box. `_step(case, key, status, detail)` records a step. `acknowledge()` opens a tuition approval (only then is the 2-minute confirmation created). When the readers disagree on a money intent, `_check_reading()` returns `CLARIFY`; the UI resends with `reading_confirmed: true`. `_small_university_fee()` sends non-tuition university bills within the family limit straight to the student (re-checked in `_recheck_payment()`). `_safe_alternative()` offers the payee's own bill after a block.
- [studybridge/payments.py](studybridge/payments.py) `PaymentBook` holds the rules on stored data: `gate1()` raises `PaymentBlocked(code, detail)` carrying `.checks`, plus `everyday_route()`, `bank_check()` (a daily card total), `find_allowance()`, `bank_review()`, `decide()` (also limit raises and account changes, which need `phone_verified` and a hold applied in `expire()`). Payee, account, payee type and amount come from `data/sample_profile.json`, never from the message, except food/QR amounts (capped). Reported new account numbers live in `_new_accounts`, never in requests or snapshots. `_xray()` and `_doc()` build the view data for the X-ray and the invoice viewer (account numbers masked).
- [studybridge/reasons.py](studybridge/reasons.py): every refusal code with its meaning and fix step. A new code must be added here (`PaymentBlocked` asserts it exists) and in `static/reasons_bn.js` (a test checks). Non-refusal outcomes are in `STATUS`.
- [studybridge/sandbox.py](studybridge/sandbox.py) `Sandbox.act(actor, action, args)` is the single entry point for the web UI, the stories and the demo. The actor comes from the screen; `ACTOR_ACTIONS` in [security/permissions.py](studybridge/security/permissions.py) decides who may do what; the tier (`TOOL_TIERS`) is a separate check. `set_llm` switches Qwen on/off (fails closed with `LLM_UNAVAILABLE`). `Sandbox.impact` counts scams stopped. `state.py` saves and restores state with `--state`.
- [studybridge/slots.py](studybridge/slots.py): Qwen writes numbers as `{placeholders}`; code fills them from the facts and cuts sentences with typed digits. The guard (`security/guard.py`, `enforce_grounding`) runs afterwards for status words and banned terms.
- [studybridge/stories.py](studybridge/stories.py): the 31 stories as data (step = actor, action, args, caption, expected code; `$request`/`$pending`/`$used` placeholders). Tests, `demo.py` and the UI autopilot all run them. If you change behaviour, update the expected codes here.
- [studybridge/clock.py](studybridge/clock.py) `SandboxClock`: all expiries read it. Tests, demo and stories start frozen at 2026-10-13 09:00; the web UI ticks.
- Funding: institution bills go by `wallet.send` (cheapest sandbox provider delivering the exact amount); everyday payments by `wallet.card_pay`. Hard caps (`config.LIMITS`) and balance are checked in `agent._guardrails`.
- v0.4 additions. [security/threats.py](studybridge/security/threats.py) names an attack (OWASP LLM Top 10 2025 ids) for refusals, the red alert and the scam score; `agent.handle()` runs flood limit → length limit → `threats.detect` → `_stop_before_qwen` (so Qwen never sees an attack) → approve-in-chat check → parse. Detection is labelling only: gates do not depend on it. New refusal codes `SECRET_REQUEST`, `INPUT_TOO_LONG`, `TOO_MANY_MESSAGES` (also in `reasons_bn.js`, whose Bangla is a first draft). `guard.deobfuscate()` undoes spacing, look-alike characters and leetspeak before the injection check. When only Qwen reads a money intent, `_check_reading()` offers Qwen's reading as a code-written question (single use, tied to the message). [invoicelab.py](studybridge/invoicelab.py) makes lab bills and seeded random bills with the answer the plan requires (`run_check`, also used by the demo's "Random bills" section and by `Sandbox._check_random_bills` in a throwaway sandbox); lab actions are operator-only. `challenge.py` holds 35 attacks in 7 groups, each with an `expect` outcome that a test checks; the 5 "cases" attacks carry a `source` from `cases.py`. The UI's red alert is `body.redalert` plus a `popover="manual"` banner (CSSOM/class only, no inline style).
- Extras (v0.4, `tests/test_extras.py`): `scamcheck.py` (rules-only message checker and quiz; pasted text never goes to Qwen or the audit log, only signal names go to Qwen), `cases.py` (sourced scam patterns), the family **safe word** (`PaymentBook.set_safe_word`/`safe_word_reason`, checked in `decide()`; only a salted PBKDF2 hash is stored and saved in state; codes `SAFE_WORD_REQUIRED/WRONG/LOCKED`) and **new payees** (`add_payee`, `cooling_left`, Gate 1 code `PAYEE_COOLING_OFF`, 48 h; sample payees have no `saved_ts` so stories are unchanged). `web.allowed_hosts()` adds `RENDER_EXTERNAL_HOSTNAME` and `STUDYBRIDGE_ALLOWED_HOSTS` to the host check. The inbox is not rebuilt while a field in it has focus (the page re-renders every second).
- Models (`llm.py`): `OllamaClient` and `OpenAICompatClient` share `available()/chat_json()/chat_text()` plus `model`, `label`, `reason`; `make_client(url, model)` picks hosted when a URL or `GROQ_API_KEY`/`STUDYBRIDGE_LLM_KEY` is set. The key comes only from the environment, only goes in the Authorization header and is cut from error texts (they reach the audit log). A local per-minute/per-day budget raises `LLMError`, which the agent already treats as "Qwen did not answer". Tested against a fake local server in `tests/test_hosted_llm.py`; never call a real provider in tests. The demo's `summary.json` has `llm_provider`.
- `tools/opinion_collect.py` is a hand-run research script (Reddit/YouTube/X posts sorted into themes); it is not imported by the app and its tests use fake network functions. The research write-up is `docs/PROBLEM_RESEARCH.md`.
- Other modules: `xray.py` (what is wrong on a bill), `challenge.py` ("Try to scam it" attacks, `/api/attacks`), `bangla.py` (Banglish/Bangla words for the rules reader), `fx`, `remittance`, `credit`, `budget`, `tuition`, and the hash-chained audit log with masking and a `.head` file.
- [web.py](studybridge/web.py) and `static/` (`index.html`, `app.js`, `style.css`, `i18n.js`, `reasons_bn.js`): stdlib server with a strict CSP (no inline script/style, so use CSSOM for dynamic styles), the `X-StudyBridge: 1` header on POSTs, and `textContent` only. Endpoints: `/api/state`, `/api/act`, `/api/story`, `/api/stories`, `/api/attacks`, `/api/audit/{tail,verify,tamper-test}`. `/?story=A6` (or `all`) autoplays; `/?tour=1` plays the judge tour.

## Tests

- `tests/test_data.py` checks `data/sample_profile.json` (re-derives each invoice's Gate 1 code independently) and fails if any code in `reasons.py` is not exercised by a test or story. Run it after any data or reason-code change.
- Qwen sees only `llm_view(result)`: free-text keys (`note`, `purpose`, `memo`, `warnings`, `summary`, ...) are stripped. Keep it that way; `test_note_purpose_and_memos_never_reach_qwen` records every prompt.
- `PaymentBook` shares the wallet's payee dicts (`payees=wallet.beneficiaries`), so an applied account change is what the wallet pays. Don't copy them.
- The web handler refuses non-local `Host`/`Origin` (DNS rebinding); tests start it on a random port.
- Tests use a `FakeLLM` (no Ollama) and a frozen clock. Guard regression tests contain real qwen2.5:7b sentences; don't weaken them.
- When behaviour changes, keep counts and claims in sync in [README.md](README.md), [docs/TECHNICAL_DOCUMENTATION.md](docs/TECHNICAL_DOCUMENTATION.md), [docs/SECURITY_SELF_ASSESSMENT.md](docs/SECURITY_SELF_ASSESSMENT.md) and [evidence/README.md](evidence/README.md) (labels as in `../CLAUDE.md`).
